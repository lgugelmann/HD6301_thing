# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A retro-inspired computer built around the **Hitachi HD6301V1** — an 8-bit CPU derived from the Motorola 6801. The repo contains:
- A full-system C++ emulator (CPU, graphics, audio, I/O peripherals)
- An HD6301 assembly monitor program and user applications
- A disassembler for HD6301/6801 instructions
- Pico firmware for HDMI graphics output and USB programming interface

## Build

The root CMake build covers the emulator, disassembler, and assembly targets. Configure once then build:

```sh
mkdir build && cd build
cmake .. -G Ninja
ninja
```

Key CMake options:
- `-DGPERFTOOLS_BUILD=ON` — enable gperftools CPU profiling
- `-DUSE_CLANG_TIDY=ON` — enable clang-tidy static analysis
- `-DTSAN_BUILD=ON` — enable ThreadSanitizer

**Dependencies**: SDL3 (required), RtMidi (optional, enables MIDI). The ASL assembler and p2bin are built automatically from the `dependencies/asl` submodule — no separate install needed.

## Tests

```sh
ctest                  # all tests
ctest -R instruction   # instruction tests only
ctest -R emulator      # C++ peripheral/CPU tests only
```

Two test targets:
- **`emulator_tests`** — GoogleTest tests for peripherals (W65C22, SPI, etc.)
- **`instruction_tests`** — declarative tests in `emulator/testdata/instructions/*.test`

### Declarative instruction test format

Files in `emulator/testdata/instructions/` are auto-discovered. Test cases separated by `---`:

```
---
name: immediate
memory: 80 05        # hex bytes placed at PC
setup: a=10          # initial register state
at 0042: 05          # pre-load byte at address
expect: a=0B N=0 Z=0 V=0 C=0
cycles: 2
```

Defaults when not specified in `setup`: `a=00 b=00 x=0000 sp=F000 pc=0020 sr=C0`. Only fields in `expect` are checked.

## Running the emulator

```sh
./emulator --rom_file=../asm/rom.bin --sd_image_file=../sd_card/image.img
```

The `--sd_image_file` is optional. Pass `--symbols_file=asm/symbols.txt` (generated by `ninja rom`) to show real symbol names in the disassembly view. Run `./emulator --helpfull` to see all options. For verbose instruction-level logging, add `-v 3 --stderrthreshold 0`.

## Assembly (ROM)

From the build directory, CMake targets:
- `ninja monitor` — assemble monitor.bin (placed at `$D000`)
- `ninja programs` — assemble programs.bin (placed at `$8000`)
- `ninja rom` — combined monitor + programs ROM; also generates `asm/symbols.txt`
- `ninja monitor_prog` / `ninja programs_prog` / `ninja prog` — flash to hardware via pico_programmer

The assembler is AS (http://john.ccac.rwth-aachen.de:8000/as/), which supports the 6 extra HD6301 instructions beyond 6801.

## Architecture

### Emulator (`emulator/`)

**`hd6301_thing.{h,cc}`** — top-level system orchestrator. Manages all peripherals, runs the emulation loop in a separate thread, exposes breakpoints/stepping/state introspection. Thread-safe via Abseil mutexes.

**`cpu6301.{h,cc}`** — HD6301V1 CPU core: instruction execution, register state, interrupt handling.

**`address_space.{h,cc}`** — O(1) lookup-table based memory routing. Maps 16-bit addresses to peripherals (replaces former linear scan).

**Peripherals**: `graphics.cc` (pico_graphics board), `w65c22.cc` (WD65C22 VIA), `spi.cc` + `sd_card_spi.cc` (SD card via SPI), `sound_opl3.cc` (OPL3 via Nuked-OPL3), `tl16c2550.cc` (UART/MIDI board), `hd6301_serial.cc` (SCI), `timer.cc`, `ioport.cc`, `ps2_keyboard_6301.cc`.

**`graphics_state/`** — shared library between the emulator and Pico firmware for parsing graphics commands.

### Assembly software (`asm/`)

**Memory map**:
- `$D000` — monitor program (system init, CLI, IRQ handlers, standard library)
- `$8000` — user programs preceded by a program registry

**`monitor.s`** — system monitor with `SECTION`-scoped organization. Public symbols exported via `PUBLIC`/`SHARED` macros and collected in `monitor.inc` for use by programs.

**`programs/`** — individual user programs (`snake.s`, `graphics_test.s`, `midi_synth.s`, etc.). Each exports a `program_name_start` label. The file `programs.s` is auto-generated by `generate_programs_list.py`.

**`include/`** — shared headers: stdlib, keyboard handling, PS2 decoding, hardware register constants, memory map, FAT16 filesystem access.

### Disassembler (`disassembler/`)

`disassembler.{h,cc}` — HD6301/6801 disassembler with annotation support (code/data discrimination), labels, and cross-references. `instructions6301.h` contains the 256-entry instruction table.

`load_symbols(path)` loads a `symbols.txt` file (format: `ADDR name` per line) generated by `asm/extract_symbols.py`. Dotted local labels (`foo.bar`) are displayed as `.bar`. Call before `disassemble()` so real names take priority over auto-generated `loc_XXXX` labels.

## Code style

- C++23, Google style (`.clang-format` configured)
- clang-tidy checks: `abseil-*`, `modernize-*`, `performance-*`, `readability-*` (with some exclusions — see `emulator/CMakeLists.txt`)
- Abseil used for logging (`LOG`, `VLOG`), status/error handling, and synchronization

## Known emulator limitations

- Mode selection doesn't happen — CPU always behaves as mode 2/4
- SCI: no overrun/framing checks, no wake-up
- Timer: only counting/overflow, no P2 modes
- TL16C2550: basic emulation, second UART not implemented
- TSan may flag a false positive with SDL/PulseAudio audio buffers
